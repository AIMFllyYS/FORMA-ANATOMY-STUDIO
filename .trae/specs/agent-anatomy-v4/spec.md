# Forma v4：Agent 教学能力升级与系统解剖 3D 资产/命名体系重建 — 产品需求规格

## Overview

- **Summary**：对 Forma 解剖学习工作台进行一次系统性升级，包含四条主线：① Agent 工具行为限额可在两个界面配置并遵守工具调用协议；② 建立规范解剖命名层（拉丁/英文/中文规范名）与更细的功能分组，重点补齐肌肉与内脏；③ 重建高分辨率模型来源管线（Z-Anatomy 重导出为主，BodyParts3D 4.0 为备选源），支持来源/档位切换；④ 新增 Agent 可驱动的时间轴动画能力（结构组装、关节教学运动、相机编排、多态高亮），以腕关节为首个贯通样板。
- **Purpose**：让学习者按系统解剖学的真实认知路径（方位定向 → 骨支架组装 → 关节配对与运动轴 → 跨关节肌群的起止与功能 → 主动回忆）学习；让 Agent 能在授权边界内自动发现素材、编排并播放带讲解节奏的动态课程。
- **Target Users**：中文系统解剖学自学者（医学生/相关专业）；需要离线可用、数据来源可信、名称规范、可观察可复习的 3D 学习环境。

## Goals

- Agent 的轮次、单轮工具调用数、画面停留时长、请求超时等行为上限可由用户在界面设置并持久化，默认值安全，超出即停。
- Agent 服务端与浏览器侧严格遵守 OpenAI Chat Completions 工具调用协议与白名单/校验/批准规范，跟随 Vercel AI SDK 官方推荐的"服务端只出工具意图、浏览器批准后执行"架构。
- 每个实际加载的源对象都显示**有出处、可溯源**的规范名称：拉丁名（TA2 体系）、英文名、中文规范名/教材常用名、侧别；命名层覆盖肌肉、内脏、脉管、神经等当前裸名或缺失系统。
- 结构树按"系统 → 区域 → 功能群 → 亚群 → 结构"分层；肌肉分组细化（上肢示例：上肢带肌/肩肌、臂前群、臂后群、前臂前群、前臂后群、手肌；下肢、躯干、头颈同理）。
- 提供可复现的高分辨率模型导出管线（balanced / HD 两档），模型来源与分辨率档位可在界面切换；署名与许可链完整。
- 应用内新增确定性的时间轴动画播放器；Agent 新增组装、教学运动、相机编排、多态高亮等白名单工具，可设置每步时长/角度/顺序，受用户全局上限约束。
- 以腕关节（桡腕关节）为端到端样板：Agent 能自动发现桡尺骨、近远排腕骨、跨腕肌群，按"拼装 → 六面观察 → 屈伸/桡尺偏教学运动 → 肌群功能 → 测验"完成一节动态课。

## Non-Goals

- 不做肌肉伸缩变形、蒙皮、肌腱驱动解算、碰撞或经验证的人体生物力学模拟；肌肉随关节运动仅作**刚性成组**教学演示并明确标注。
- 不做 CT/MRI 体绘制、骨小梁/内部重建、手术/患者诊断用途。
- 不在浏览器运行时引入 Draco/Meshopt 解码器或 Three.js/React；不做引擎重写。高模通过静态 GLB（可量化顶点）+ 传输层 gzip + 分系统懒加载承载。
- 不批量抓取或再分发全国科技名词委《人体解剖学名词》数据；中文规范名以开放数据（Wikidata CC0 等）+ 人工/教材校对生成，逐条记录审校状态。
- 不把模型二进制（GLB/BLEND/OBJ/STL）、node_modules、构建产物提交进 Git。
- 不在本环境用真实付费模型完成服务端端到端验收（沿用现有边界，提供模拟协议测试与手工验证入口）。
- AI SDK v7 迁移不在本轮实施（锁定 v6 并加固），但代码需为迁移留好接口。

### 调研关键事实（2026-09 核实，来源在设计说明中留档）

1. **名称缺失是映射问题而非模型问题**：现用 GLB 节点本身为英文 TA 名（如 `External abdominal oblique muscle.l`、`Stomach`），`.l/.r` 标侧；骨名短（`Scapula.l`）能命中，肌肉为完整 TA 多词名、本地只有短名（`external oblique`），词界匹配失败而回退裸英文名；内脏卡仅 5 张。Z-Anatomy 约定：`.j` 空对象、`.g` 文字对象、名末撇号表示未建模。
2. **减面量化**：上游重导出相对 Z-Anatomy 源（细分后约 1048 万面）保留比例：骨骼 ~46%、关节 ~42%、肌肉 **18%**、心血管 **11%**、神经 17%、内脏 36%；现用七套合计约 218 万面。
3. **来源与许可**：Z-Anatomy（CC BY-SA 4.0，源自 BodyParts3D）提供 86.7MB Blender 模板（Startup.blend 约 293MB）与 TA2.csv（英/拉 +5 语种，无中文）；DBCLS BodyParts3D 4.0 批量 OBJ 现渠道标注 **CC BY 4.0**（页面存在旧 BY-SA 链接残留，商用需书面确认，本项目开源教育使用风险低但需留档）；Wikidata（CC0）可用 FMA ID(P1402)/TA98(P1323)/TA2(P7173) 取拉丁名与中文标签；UBERON/FMA-OBO（CC BY 3.0）可作层级骨架；中文名词委无开放 ab 批量数据，仅作人工校对标尺。
4. **Agent SDK**：AI SDK v7 已于 2026-06 GA，`ToolLoopAgent` 保留（`stepCountIs`→`isStepCount`），v6 仍在维护（registry `ai-v6`）；官方明确支持"工具无 execute → 意图转发客户端"模式；建议入站历史做 JSON Schema 校验、浏览器侧 system 消息应剥离；限额属客户端循环职责。
5. 引擎现支持 `KHR_mesh_quantization`（[mesh-engine.js#L25](file:///d:/projects/Dev-Web/Forma-Anatomy-Studio/web/mesh-engine.js#L25)），拒绝 Draco/Meshopt/蒙皮/变形目标；有 750MB 单文件上限、IndexedDB 缓存、SHA-256 身份。

### 第一性原理：系统解剖学应该怎么学

- **先方位后结构**：解剖学姿势、方位术语、面与轴是一切讲解的坐标系。
- **骨是支架**：先整体骨学，再以骨面标志作为肌附着与关节配对的锚点。
- **组装即记忆**：如腕部学习顺序＝桡尺骨远端 → 近排腕骨（舟月三角豆）→ 远排（大小头状钩）→ 掌骨 → 关节盘/韧带 → 跨腕屈/伸肌群，按层级拼装比直接看整手更易建立空间关系。
- **关节＝骨面配对＋运动轴**：先认组成与关节面，再谈轴、自由度与运动术语；运动必须能被时间化（慢速、分步、可重复）。
- **肌功能＝跨轴起止**：肌群按筋膜鞘/功能群（如前臂前群屈肌、后群伸肌）成组学习，功能相对关节轴定义；没有变形数据时，用"肌群随远端骨刚体重组 + 收缩态高亮"诚实表达，不伪装形变。
- **主动回忆收尾**：每个观察循环以测验/辨认结束。

## Functional Requirements

### A. Agent 行为配置与协议合规

- **FR-1**：用户可在"设置中心"（顶栏/更多菜单与 Agent 面板均可进入）与 Agent 输入区旁的"助教设计"快捷条配置并持久化：最大工具轮次、单轮最大工具调用数、画面停留上限（秒）、单次请求超时（秒）、默认权限模式（智能批准/全部允许/每次批准）、动画总时长上限（秒）。
- **FR-2**：所有限额具备安全默认值与硬边界（钳制），非法/越界输入永不触达执行器；配置迁移自现有 `forma-agent-config-v3`，旧版用户无感知。
- **FR-3**：Agent 循环严格遵守配置：到达轮次上限即停并明确提示；工具调用按到达顺序执行，单轮超限整体拒绝并回送可自纠的错误；动画/停留计时到达上限自动收尾；停止按钮随时可中断。
- **FR-4**：浏览器执行器对每个工具调用执行统一 JSON Schema 校验（类型、枚举、范围、长度、必填、额外字段拒绝），校验失败不改变画布并把错误作为工具结果返回模型。
- **FR-5**：agent-server 加固：剥离浏览器入站消息中的 `system` 角色（系统指令只来自服务端）；用 JSON Schema 校验器校验入站 tool_call 参数；名称白名单随工具集同步；鉴权、CORS、限流、2MB 体限、超时常量不回归。
- **FR-6**：工具定义成为浏览器与服务端的**单一事实源**（含名称、描述、参数 schema、写/读标记、中文名、图标），构建与测试自动校验两端一致；新增工具不再需要手工同步多处。
- **FR-7**：依赖版本精确锁定并提交 lockfile；`npm test`、`node --check` 在无网络模拟下通过。

### B. 规范命名层与功能分类

- **FR-8**：新增独立于知识卡的**命名层数据**：每条身份记录含稳定 id、源名匹配模式（或 FMA/TA id）、中文名、拉丁名、英文名、侧别、系统、区域、功能群、亚群、映射方法与审校状态（auto/pending/reviewed）。
- **FR-9**：对当前七套上游 GLB 的全部实际节点，肌肉与内脏系统的中文规范名显示覆盖率（auto 及以上）≥ 90%；无法可靠映射的节点保留源名并显式标记"未规范命名"，绝不张冠李戴。
- **FR-10**：命名匹配兼容 Z-Anatomy 命名约定（`.l/.r` 侧别、多词 TA 全名、亚部、`.j/.g/撇号` 特殊对象过滤），并优先于旧的短名包含匹配；知识卡通过稳定 id 与命名层关联（现有 465 张卡不丢失、不误挂）。
- **FR-11**：结构树/目录/图层按新分类层级分组；肌肉系统至少呈现：头颈肌、躯干肌（背/胸/膈/腹）、上肢带肌与肩肌、臂肌（前群/后群）、前臂肌（前群/后群）、手肌（鱼际/小鱼际/蚓状/骨间等）、髋肌、大腿肌（前/后/内侧群）、小腿肌（前/后/外侧群）、足肌；内脏按系统解剖学系统（消化/呼吸/泌尿/生殖/腹膜/心血管/淋巴/感觉器/神经）归组。
- **FR-12**：搜索、悬浮提示、标签、讲解页、Agent 工具输出统一显示"中文名 · 拉丁名/英文名 · 侧别"，拼音可用；UI 明确区分"已审校/待审/未映射"三种命名可信度。
- **FR-13**：命名数据生成可复现（脚本 + 原始开放数据缓存 + 人工覆表层），生成物（JSON）入仓库，生成脚本入仓库；不提交名词委数据。

### C. 高分辨率模型管线与来源管理

- **FR-14**：模型来源注册表（版本化数据文件）描述每个来源/档位的 URL、文件映射、质量说明、三角面预算、许可与署名；应用"模型资源"界面可选择来源与档位（标准/balanced/HD），选择对后续加载生效，已缓存资产按 SHA 区分不混淆。
- **FR-15**：Blender 无头导出脚本支持七系统（在现有四系统上补齐内脏/心血管/淋巴）、两档三角面预算、曲线对象转网格、特殊对象过滤、节点 extras 写入稳定解剖 id，并产出 manifest（节点名、对象数、面数、体积、许可链）。
- **FR-16**：HD 档相对当前上游档，肌肉系统三角面 ≥ 2 倍、心血管与神经 ≥ 2 倍；balanced 档介于两者且全套可在 8GB 内存机器上分系统流畅浏览（指标见 AC）。
- **FR-17**：加载链路支持 gzip 透明解压（远程 `Content-Encoding` 与本地 `.glb.gz` 导入均覆盖），量化 GLB 经现有路径正确解析；既有 SHA 校验、缓存、单文件导出、750MB 上限行为不回归。
- **FR-18**：来源与许可界面完整展示 BodyParts3D → Z-Anatomy → 改编版本署名链、CC BY-SA 4.0 / CC BY 4.0 区别与"教育用途、未完整医学审校、仅成年男性"等限制；自托管 HD 源有文档说明。

### D. 时间轴动画引擎

- **FR-19**：新增确定性时间轴播放器：支持多个时间重叠/串行片段（tween），可驱动对象显示位移（组装）、刚体旋转矩阵（运动）、相机（目标/yaw/pitch/跨度）、高亮态、爆炸程度、标签；具备播放/暂停/恢复/停止、时长、延迟、缓动、循环计数；任何新画布操作或停止按钮可立即中断。
- **FR-20**：动画时长/角度/对象数受设置上限钳制；尊重 `prefers-reduced-motion`（降级为直接呈现终态＋文字说明）；动画状态可撤销/场景返回时清理；动画播放期间禁止拾取状态错乱。
- **FR-21**：提供"组装"原语：给定有序结构组（按功能群或显式 id 列表），从爆炸位移按每步时长与缓动归位，可伴随相机推近与分组高亮；可反向拆解。
- **FR-22**：提供"关节教学运动"原语：以课程数据声明的锚点规则从**真实已加载几何**计算教学近似轴（两端点，包围盒/中心推导，带容差失败提示），驱动移动骨与跨关节肌群（刚性成组）在角度区间内随时间往复；界面与 Agent 输出始终标注"教学近似轴/刚体演示，非生理活动度与生物力学认证"。
- **FR-23**：提供"相机编排"原语：六面/解剖方位视图（前/后/上/下/内/外，需朝向校准状态）、绕结构定时环转、多视点停留；源坐标未校准时不得自称解剖学方位。
- **FR-24**：提供多态高亮（普通/强调/序列焦点/收缩态至少四态，用颜色或描边区分），并可在时间轴中切换。
- **FR-25**：关节学习面板升级为可播放课程：组成逐项 → 组装 → 六面观察 → 运动演示（含移动肌勾选、角度区间、时长、循环）；现有"手动两点设轴"保留为高级模式。

### E. Agent 教学工具与课程

- **FR-26**：新增只读工具：分类浏览（系统/区域/功能群、各组对象数与加载状态）、课程读取（关节的组装顺序、组成、运动定义、主动/拮抗肌群、教学轴锚点规则）；让 Agent 不加载模型也能先规划、缺料时明确告知并给出需要载入的系统名。
- **FR-27**：新增写工具（均需按权限模式批准）：多态高亮、组装播放、关节运动播放、相机编排、停止动画；参数仅含结构 id/课程枚举/时长/角度/顺序，所有副作用由浏览器时间轴执行，服务端不执行副作用。
- **FR-28**：系统提示词与工具描述内置教学法约束（发现→确认 id→申请播放→边停边讲→测验）、方向术语使用规则、诚实边界（近似轴、刚体肌、未加载不编造、未审校不冒充）、节奏规则（按 hold/时长讲解、不刷屏切镜）。
- **FR-29**：腕关节作为首个数据贯通的样板课程：组装顺序、运动轴锚点（屈伸冠状轴、桡尺偏矢状轴的近似几何规则）、移动骨组（腕骨+掌骨成组）、跨腕肌群（前群屈肌/后群伸肌/尺侧腕屈伸/桡侧腕长伸短伸等）以稳定 id 编入课程数据；其余七关节至少升级为新 schema（字段可缺，缺失明确标注）。
- **FR-30**：端到端验证：在模拟兼容服务（无真实密钥）与浏览器夹具下，Agent 收到"带我学习腕关节的运动、肌肉变化和骨的组成"类指令时，能调用只读工具发现素材、按序申请并播放组装/六面视图/两种运动、报告缺失系统、以测验收尾；批准拒绝时不绕过、不重复请求。

## Non-Functional Requirements

- **NFR-1 安全**：所有模型/工具/来源/用户输入文本经转义显示；无 innerHTML 注入面；密钥不入存储导出/学习记录/Git；服务端不记录 prompt 与密钥；错误信息脱敏。
- **NFR-2 兼容与离线**：单文件 HTML 仍可离线打开；无 CDN/npm 运行时依赖；Chromium/Edge 与移动浏览器布局可用；IndexedDB 不可用时降级提示。
- **NFR-3 性能**：标准档现状不回归；balanced 全套（约 300 万面级）在代表机型交互帧率 ≥ 30fps；HD 分系统加载（单系统 ≤120 万面级）交互 ≥ 30fps；首屏骨骼加载 ≤ 现状水平；性能证据来自真实浏览器实测（夹具不计医学认证）。
- **NFR-4 可维护**：工具定义单一事实源；命名/课程/来源均为版本化数据文件；构建器与测试同步覆盖；新增一类结构不需改引擎。
- **NFR-5 诚信与合规**：许可署名链完整；所有近似/未审校/教学演示内容有持久且显著的标注；不出现"已医学认证/临床可用"类表述。
- **NFR-6 可测**：Python 构建/HTTP 测试、Node 协议测试、浏览器夹具测试全部更新且通过；新增命名/校验/动画逻辑具备夹具级自动化回归。

## Constraints

- **Technical**：原生 JS + WebGL2 自研引擎，无前端框架；Python 3.10+ 构建；Node ≥22 agent-server；Git 提交模型二进制；Windows + PowerShell 环境；模型源 CORS（GitHub raw 可用，自托管需同源/允许跨域）。
- **Business**：项目开源（MIT 代码），模型数据 CC BY-SA 4.0 / CC BY 4.0，须署名且衍生数据同许可；中文命名需标注审校状态。
- **Dependencies**：Blender（本机安装，无头导出）；Z-Anatomy 官方模板下载；Wikidata/TA2.csv 联网获取一次并缓存；agent-server 依赖仅在 server 目录安装（ai@v6、@ai-sdk/openai-compatible@2、Ajv）。

## Assumptions

- 用户跳过澄清提问，按推荐项决策：① 设置中心 + 助教设计区双入口；② Z-Anatomy 重导出为主 + BodyParts3D 备选的双管线；③ 全套教学动画工具（含教学近似轴）；④ 授权在本机安装 Blender 并实际生成高模 GLB。
- Blender 可由脚本自动下载安装（官方 zip/msi），Z-Anatomy zip 可从 GitHub 拉取；若机构网络阻断，则管线脚本与文档先交付、实体生成标记 blocked。
- 现有 WebGL2 拾取 ID 空间（24bit）在 HD 对象数下仍充足（现 2914 对象，HD 同量级）。
- 机型性能以开发机实测数据为准，达不到门槛的档位降档发布而非降低标注标准。

## Acceptance Criteria

### AC-1：Agent 行为限额可配置且被强制（rule）

- **Given** 用户打开设置中心或助教设计区，**When** 修改轮次/单轮工具数/停留/超时/动画总时长并保存，**Then** 值被钳制在安全区间、写入本地存储并在下次对话立即生效；旧 v3 配置自动迁移。
- **Pass Condition**：越界/非法值无法保存为越界配置；运行中到达任一上限必然停止并给出中文提示；代码与浏览器测试可证明。
- **Evidence**：[agent.js](file:///d:/projects/Dev-Web/Forma-Anatomy-Studio/web/agent.js) 配置与循环代码；浏览器夹具测试（含限额触发用例）；手工设置录屏/截图。

### AC-2：工具定义单一事实源 + 双端 Schema 校验（rule）

- **Given** 任意一次 Agent 工具调用（直连或经 server），**When** 参数缺字段、超范围、含额外字段或名称不在白名单，**Then** 浏览器不改变画布并回结构化错误；server 在入站转换时拒绝该消息；两端工具集（名称/schema/读写标记）一致性由自动测试断言。
- **Pass Condition**：新增工具只改一处事实源；`node --test` 与构建后夹具全部通过。
- **Evidence**：共享工具定义文件；agent-server 测试；tests/ 浏览器夹具；代码评审差异。

### AC-3：服务端协议加固与版本锁定（rule）

- **Given** agent-server 收到含伪造 system 角色、非法参数、越权名称的历史消息，**When** 执行转换，**Then** system 被剥离、消息被拒或错误返回；健康检查/鉴权/CORS/限流行为不回归；依赖精确锁定且 lockfile 入库。
- **Pass Condition**：protocol 测试新增上述拒绝用例并通过；`npm ls` 显示 ai 6.x 与 @ai-sdk/openai-compatible 2.x 精确版本；`npm start` 配置校验仍有效。
- **Evidence**：[protocol.mjs](file:///d:/projects/Dev-Web/Forma-Anatomy-Studio/agent-server/protocol.mjs)、protocol.test.mjs、package-lock.json、SERVER_HTTP_RESULTS。

### AC-4：七系统规范命名覆盖率与可信度标注（rule）

- **Given** 七套上游 GLB 的全部网格节点清单（脚本提取），**When** 经命名层解析，**Then** 肌肉与内脏节点中文命名覆盖率 ≥ 90%，每条记录带映射方法与审校状态，未命中节点保留源名并标"未规范命名"。
- **Pass Condition**：覆盖率报告（按系统/方法分组）随生成物产出；抽样 30 个肌肉 + 20 个内脏名称由人工核对无误挂（可用教材/术语在线对照记录）。
- **Evidence**：命名生成脚本、nomenclature 数据、覆盖率 JSON/MD 报告、抽样核对记录。

### AC-5：细化的功能群分类在 UI 全链路一致（rule）

- **Given** 加载肌肉系统后，**When** 浏览结构树/目录/图层/搜索，**Then** 呈现"系统→区域→功能群→亚群"层级，上肢含肩带/臂前后群/前臂前后群/手肌分组，内脏按系统解剖学系统归组；筛选、计数、显隐按组正确。
- **Pass Condition**：浏览器夹具断言关键分组标签存在且组内对象非空；手工核对分组归属抽样无错。
- **Evidence**：tests 夹具截图与断言；[app.js](file:///d:/projects/Dev-Web/Forma-Anatomy-Studio/web/app.js) 渲染代码。

### AC-6：高模导出管线可复现且面数达标（rule）

- **Given** 本机已装 Blender 并下载 Z-Anatomy 模板，**When** 运行导出命令产出 balanced/HD 七系统 GLB 与 manifest，**Then** 肌肉/心血管/神经 HD 面数 ≥ 现用档 2×；GLB 可被自研引擎解析（静态、无 Draco、节点名与 extras 完整）；manifest 记录面数/对象/许可。
- **Pass Condition**：导出脚本一次命令成功；manifest 数字与引擎解析数字一致；产物不入库。
- **Evidence**：tools/export_blender.py、models/ 下 manifest（仅清单入库）、解析验证脚本输出。

### AC-7：来源/档位可切换且加载链路兼容（rule）

- **Given** 用户在模型资源界面选择来源与档位，**When** 载入任一系统，**Then** 注册表对应 URL 被使用、缓存按 SHA 隔离、gzip/量化 GLB 正确载入，标准档与现有行为不回归；自托管路径有文档。
- **Pass Condition**：本地静态服务器手测三档加载（标准/balanced/HD 各至少一系统）；缓存切换不串模型；旧缓存可继续用。
- **Evidence**：[core.js](file:///d:/projects/Dev-Web/Forma-Anatomy-Studio/web/core.js) 来源注册表代码；浏览器实测记录；licenses 文档。

### AC-8：时间轴动画能力与安全边界（rule）

- **Given** 已加载关节组成并定义课程动画，**When** 播放组装/运动/相机编排/高亮序列，**Then** 动画按声明时长/顺序/缓动执行、可停可跳、reduced-motion 下降级为终态、超时受上限钳制、结束后画布状态与声明一致且可撤销返回。
- **Pass Condition**：自动化夹具（合成几何，明确非解剖）验证时间轴语义；手工真机验证一次组装+一次腕运动。
- **Evidence**：动画播放器代码与测试；浏览器测试录像/截图。

### AC-9：腕关节 Agent 课程端到端贯通（rule）

- **Given** 模拟兼容服务 + 已缓存骨骼/关节/肌肉模型，**When** 用户发出腕部学习请求，**Then** Agent 经只读工具发现桡/尺、近远排腕骨、跨腕肌群，申请并（批准后）驱动组装→六面视图→屈伸与桡尺偏教学运动→肌群高亮→测验；缺料时明确要求加载对应系统；拒绝授权时不绕过。
- **Pass Condition**：脚本化浏览器测试断言工具调用序列、动画实际播放（截图像素/状态变化）、最终消息含教学要素与边界声明。
- **Evidence**：tests 新增 e2e 用例与 _runtime 证据；工具序列日志。

### AC-10：命名与教学内容的解剖学质量（rubric）

- **Dimension**：名称准确性、分组合理性、课程描述（组成/运动/肌群）与通用《系统解剖学》教材的一致度。
- **Scale**：1–5。**Anchors**：1＝多处错误命名或误导性动作描述；3＝常用结构正确、亚部有少量遗漏或措辞含糊；5＝抽样结构名称、分组、腕课程内容与指定教材一致且边界声明完整。
- **Pass Threshold**：≥ 4。
- **Evidence**：人工抽样核对表（≥ 50 个肌肉/内脏名 + 腕课程全文）。

### AC-11：动画与 UI 的教学体验质量（rubric）

- **Dimension**：节奏可控性、视觉清晰度、与现有水墨/玻璃设计语言一致性、移动端可用性。
- **Scale**：1–5。**Anchors**：1＝动画突兀不可控或风格割裂；3＝功能完整但节奏/视觉一般；5＝分步清晰、可暂停跟读、控件统一、窄屏可用。
- **Pass Threshold**：≥ 4。
- **Evidence**：设计走查截图（浅/深、移动/桌面）+ 试用记录。

### AC-12：HD 档真实性能（rubric）

- **Dimension**：代表机型上 HD 单系统与 balanced 全套的交互流畅度（帧率、加载时长、内存）。
- **Scale**：1–5。**Anchors**：1＝卡顿不可用；3＝可观察但交互掉帧明显；5＝交互稳定 ≥30fps、加载可接受。
- **Pass Threshold**：≥ 4 或明确降档发布说明（达不到的档位不标记为可用）。
- **Evidence**：真实浏览器性能采样（开发机硬件与浏览器版本留档）。

### AC-13：工程回归与构建（rule）

- **Given** 全部改动完成，**When** 运行 `python tools/build.py`、`python tests/test_build.py`、`python tests/server_http_test.py`、`node --test agent-server/protocol.test.mjs`、浏览器夹具套件，**Then** 全部通过；单文件导出/导入/SHA/记录白名单不回归。
- **Pass Condition**：所有命令退出码 0；结果文件更新；dist 可重建。
- **Evidence**：命令输出与 RESULTS/VALIDATION 文件。

### AC-14：文档与许可合规（rule）

- **Given** 新来源、新命名、新工具与动画上线，**When** 阅读 README/ARCHITECTURE/RELEASE_NOTES/来源弹窗/licenses，**Then** 架构扩展入口、工具清单、许可署名链、教育非临床边界全部与实现一致。
- **Pass Condition**：文档评审无过时承诺；许可链接与义务清单齐备。
- **Evidence**：文档 diff；SOURCE_NOTICES 更新。
